# 포스트 퇴고 & 수정

기존 포스트 파일을 읽고, `guides/editorial-rules.md`의 규칙에 따라 퇴고합니다.

## 입력

`$ARGUMENTS`에서 포스트 파일 경로를 받습니다.

예시:
- `/edit-post tech/2026-03-10-openclaw-rl.html`
- `/edit-post research/2026-03-05-brain-fry.html`

## 실행 단계

### Step 1: 포스트 읽기

지정된 HTML 파일을 읽고 본문 콘텐츠를 추출합니다.

### Step 2: 최우선 3원칙 검수

가이드 파일을 별도로 읽지 않습니다. **다른 검수보다 먼저** 아래 3원칙을 전체 본문에 적용합니다.

- 원칙 1 (자연스러운 한국어): 번역체 검출 및 수정, 외래어 남용 교체
- 원칙 2 (주술 근접): 주술 사이 수식어 3개 이상 → 문장 분리
- 원칙 3 (이해하기 쉽게): 1문장 1정보, 추상 → 구체 수치/행동

> **3원칙 위반은 0건이 될 때까지 반복 수정합니다.** 이 단계를 통과해야 Step 4로 넘어갑니다.

### Step 4: 자동 검수

퇴고 단계 검수입니다. `/publish-post`에서 최종 재확인합니다. 아래 항목을 자동으로 검출합니다:

**오탈자 오인 주의:** "스스로"는 오타가 아닙니다. "스스로"를 "스스로"로 교정하지 마세요. 의도된 표기입니다.

**금지 표현 검출:** 혁명적, 획기적, 폭발적 성장, 누구나 쉽게, 패러다임 시프트, 게임 체인저, em dash(—)

**문장 길이 체크:**
- 60자 초과 문장 목록 추출

**종결어미 체크:**
- 3줄 요약 섹션이 입니다/합니다 체인지 확인

**em dash 검출:**
- — 문자 사용 여부

**`<h3>` 태그 검출:**
- 본문 내 `<h3>` 존재 시 `<p><strong>` 패턴으로 교체

**문단 길이 체크:**
- 하나의 `<p>` 태그 내 문장이 6개 이상인 경우 분리 필요

**컨텍스트 문장 수 체크:**
- "왜 지금 중요한가" 섹션이 5문장을 초과하는 경우

**기술 용어 Lv.2 체크:**
- 첫 등장 시 괄호 설명이 없는 전문 용어 검출

**참고자료 형식 체크:**
- "영상 보기 ↗" 같은 축약 링크 텍스트 → URL 전문으로 교체
- APA 형식: `저자. (연도, 월). *제목* [Video/Article]. 플랫폼. URL`

**마크업 클래스 체크:**
- `methodology-box`: 인라인 스타일 없이 클래스만 사용하는지 확인 (다크모드 CSS가 style.css에 정의됨)
- `stat-card` / `stat-num` / `stat-label`: 인라인 스타일 없이 클래스만 사용하는지 확인 (다크모드 CSS가 style.css에 정의됨)

**표/차트 품질 체크:**
- 테이블이 존재하면: 전문 용어 헤더가 한국어로 변환되었는지 확인
- 핵심 수치에 `font-weight: bold; color: {카테고리 컬러}` 강조가 적용되었는지 확인
- 표 아래 출처 표기 존재 여부: `출처: 저자 (연도), Table N.` 형식
- `overflow-x: auto` 래퍼가 있는지 확인 (모바일 반응형)
- 열/행이 10개 이상이면 핵심 4~6개로 선별되었는지 확인

**빈 비즈니스 비용 섹션 검출:**
- "[비즈니스 비용: 해당 없음]" 텍스트 존재 시 섹션 삭제

**Roasting quote 동기화 체크:**
- blockquote, data-roasting-quote, JS ROASTING_QUOTE 3곳 일치 확인
- 종결어미가 높임말(~입니다/~합니다/~습니까?)인지 확인. ~다/~나?/~인가? 형태 발견 시 즉시 변환

**접속 부사 연속 사용:**
- 연속 2문장 이상 접속 부사로 시작하는 경우

### Step 5: 검수 리포트

자동 검수 결과를 리포트합니다:

```
## 자동 검수 채점 (10점 만점, 통과 기준: 9.5점)

| 항목 | 점수 | 판정 | 상세 |
|------|------|------|------|
| 금지 표현 | {N}/10 | ✅/❌ | {N}건 검출 |
| 60자 초과 | {N}/10 | ✅/❌ | {N}건 |
| 종결어미 | {N}/10 | ✅/❌ | |
| em dash | {N}/10 | ✅/❌ | {N}건 |
| 접속 부사 연속 | {N}/10 | ✅/❌ | {N}건 |
| 표/차트 품질 | {N}/10 | ✅/❌ | |
| ... | | | |

**통과: {통과 수}/{전체 수} (9.5점 미만: {미달 수}건)**

### 9.5점 미만 항목 상세
- 줄 {N}: "{문장}" → "{대체 제안}" (사유)
```

### Step 6: 자동 수정

검출된 모든 문제를 **즉시 자동으로 수정 적용**합니다 (사용자 승인 대기 없음):

1. 금지 표현 → 대체 표현으로 교체
2. 60자 초과 → 문장 분리
3. 종결어미 → 입니다/합니다 체 변환
4. em dash → 쉼표, 마침표, 괄호 대체
5. 접속 부사 연속 → 접속 부사 제거 또는 문장 재구성
6. `<h3>` → `<p><strong>` 패턴으로 교체
7. 참고자료 축약 링크 → URL 전문 APA 형식
8. 표/차트 누락 출처 → `출처: 저자 (연도), Table N.` 추가
9. 표 전문 용어 헤더 → 비개발자용 한국어로 변환
10. 표 `overflow-x: auto` 래퍼 누락 → 추가

### Step 7: 완료 보고

수정 전후 비교를 아래 형식으로 제시합니다:

```
## 퇴고 완료

### 수정 요약: 총 {N}건

### 변경 내역 (인라인 diff)
| # | 위치 | 수정 전 | 수정 후 | 사유 |
|---|------|---------|---------|------|
| 1 | 줄 {N} | ~~원문~~ | **수정문** | 60자 초과 |
| 2 | 줄 {N} | ~~원문~~ | **수정문** | 금지 표현 |

### 수동 검토 참고
- 번역체 의심 문장: {있으면 줄 번호와 문장}
- Topic Sentence 불명확 문단: {있으면 섹션명}
```

> **변경 내역 테이블**: 수정 건수가 5건 이하이면 전건 표시. 6건 이상이면 주요 변경 5건 + "외 N건" 요약.
